# 02 MVP Experience And Gameplay Spec

## 文件角色

本文件定義目前已啟用版本對玩家可見、可操作、可驗收的：

- UX 流程
- gameplay 規則
- 文案與世界觀轉譯
- 視覺與動效規範

## 產品氣質

- 奇幻冒險風
- 有儀式感
- 更像桌遊與派對工具
- 不像老派 RPG 官網
- 保持簡單、快速、直接

## 世界觀轉譯

- 餐廳 -> 據點 / 酒館 / 遠征地
- 抽籤 -> 命運指引
- 拉霸 -> 命運之輪
- 結果 -> 遠征結果
- 重抽 -> 逆天改命

## 目前可見選擇

目前前台只顯示 4 個遠征類型：

- 午餐
- 晚餐
- 飲料
- 甜點

這 4 類屬於單一決策場景中的輕量入口，不可演變成重度設定表單。

## 已啟用的 location-aware Phase 1 UX

這一段已經是目前上線行為；但目前只啟用 Phase 1，不包含 geolocation / IP-based city guess。

核心策略固定為：

`預先幫你猜，但永遠讓你輕鬆改。`

也就是：

- 不要每次打開都強迫選位置
- 永遠可看見目前使用中的城市 / 地區
- 永遠保留小而輕的人工修正入口
- 不用 full-page setup gate 打斷主流程

### First Visit

第一次進站時：

1. 若有本地記住的位置，直接使用
2. 若還沒有本地記錄，先顯示 `預計冒險地：臺北市中山區`
3. 不開啟阻塞式 setup gate
4. 使用者若想修正，再自行打開輕量 chooser

### Returning Visit

- 先讀取上次接受的位置
- first paint 直接使用
- 不重新打開 chooser
- 在預計冒險地行旁提供小型 `更改預計冒險地`

### Manual Correction

人工修正 UI 必須是輕量 panel 或 sheet，不是 full-page setup flow。

應包含：

- city dropdown
- district dropdown，並依 city 過濾
- `略過地區`
- `儲存並套用`

### Phase 2 Deferred Copy

以下文案保留到 geolocation / IP fallback 啟用時再使用：

- `要不要用你附近的地區幫你抽？`

## MVP 流程

### 1. 告示牌首頁

首頁必須包含：

- 固定兩行主標
- 主標下方的 `景點名稱 · 天氣狀態`
- 一行 `預計冒險地：城市行政區`
- 預計冒險地旁的 `更改預計冒險地`
- 一行 `預計冒險地 3 小時天氣預報`
- 兩行壓縮後的天氣資訊
- 清楚可見的全場景背景
- 同天候下可於多張相容背景之間輪替
- 若目前行政區在 `images/backgrounds/<city>/<district>/` 有正式圖，背景優先從同區同天氣的可用景點池中抽一張
- 若目前行政區尚無正式圖，背景回退到 `images/backgrounds/shared/` 的共享奇幻場景
- 使用 `images/notice/` 的奇幻分類按鈕
- 首次載入預設不選任何類型
- 使用 `images/scrolls/` 的單一主 CTA
- CTA 文案需落在卷軸安全視窗內
- 未選冒險目的時 CTA 顯示 `準備好了嗎？`
- 已選冒險目的後 CTA 顯示 `決定今日命運`
- 若目前預計冒險地在所選類別下沒有任何據點，CTA 需顯示 `目前沒有可用據點` 並保持禁用
- mobile 上 CTA 文案必須優先縮小，不可換成兩行
- 開局前就先顯示一張當前卡背
- 不可把整頁變成阻塞式設定頁
- 未選類型時提示文案顯示 `請先選擇冒險方向`

### 2. 命運揭示與翻牌

揭示區必須包含：

- 長條直式撲克牌比例卡片
- 頁面載入或重抽時依權重抽一張卡背
- 翻牌後顯示對應稀有度的正面模板
- 與卡背稀有度一致的光暈
- 簡短卡背儀式動畫
- 一次翻牌轉場
- 翻牌後的撥雲見日式揭示
- 不拖慢回合節奏的 burst / settle pulse

### 3. 遠征結果

結果畫面必須包含：

- 目的地名稱作為卡面主內容
- 卡面上不顯示命運卡規則文字
- 卡片下方、按鈕上方的距離資訊列
- 卡片下方的 `出發去吃`
- 卡片下方的 `再抽一次`

## 核心玩法規則

### Hidden Destiny Rule

- 命運卡規則仍在背景控制過濾
- 不把規則文字直接露出在卡面 UI 上
- 重抽規則仍由 hidden destiny logic 控制

### Reroll Rule

- 每局保底可重選一次
- 若抽到 `宿命重骰`，額外再送一次
- `再抽一次` 會同時重抽卡背與目的地
- 若本輪 session 已取得玩家座標，`再抽一次` 後距離資訊列會直接重算
- 次數用完後按鈕保留但禁用

### Distance Strip Rule

- 距離資訊不顯示在卡片正面
- 距離資訊不塞進 `出發去吃` 按鈕
- 位置固定為卡片下方、按鈕上方
- 不在首頁自動要求定位
- 只在結果階段由玩家主動觸發定位
- 一旦成功定位，refresh 後可直接沿用上次記住的座標顯示距離
- 直線距離依餐廳 `lat / lng` 計算
- 若店家缺 `lat / lng`，距離資訊列直接不顯示

文案規則：

- `遠征地距離你約 450 公尺`
- `遠征地距離你約 1.2 公里`
- `啟用定位後可顯示遠征地距離`
- `正在確認你的位置...`
- `請先在瀏覽器允許定位，才能顯示遠征地距離`
- `暫時無法確認你的位置，請再試一次`

### Card Back Rule

- 頁面打開就要先抽到一張卡背
- `再抽一次` 會依同樣權重再抽一張
- 稀有度與 face template 必須一致

目前權重：

- common：17.25% x4
- rare：10% x2
- epic：4% x2
- legendary：2% x1
- hidden：1% x1

## 動效規則

標準流程：

1. 先顯示卡背儀式動畫
2. 再整張牌翻面
3. 再以撥雲見日方式揭示餐廳名稱
4. 最後才顯示卡片下方操作按鈕

Reduced motion：

- 若使用者偏好 reduced motion，應直接簡化為快速揭曉
- 不可讓 reduced motion 使用者失去結果或操作能力

### Rarity Motion Rules

- `common` 不做常駐呼吸動畫，只保留卡框存在感與淡內光
- `rare` 使用最輕的白光呼吸，慢、乾淨、幅度小
- `epic` 使用更亮一階的暖金呼吸，需有能量聚散感
- `legendary` 使用更厚、更集中的紫光呼吸，像神器脈動
- `hidden` 以藍光掃描與異常流動為主，不與一般 rarity 共用同一組 pulse
- `revealing` 階段仍可比 `result` 更亮，但 `result` 階段不能把 rarity 差異收掉

## 視覺規則

- 卡片必須是直式撲克牌比例，不是正方卡
- 卡背直接用圖檔，不用抽象符印佔位
- 正面使用對應稀有度的 face 模板
- 卡片有深色切邊與陰影，但不能被黑色大色塊包住
- 稀有度光暈要明顯區分
- 卡片後方用透明光場與 aura 分離，不用深色面板
- 場景背景必須清楚可見，面板只能局部遮罩
- 主標固定兩行，不因螢幕大小跑版
- 景點 / 天氣摘要、預計冒險地、預報細節需分層，不可混成同一行
- 景點 / 天氣摘要、預計冒險地列、預計冒險地 3 小時天氣預報、兩行預報細節需共用同一組 sans 字體與暖白色階，只能用字重、字級與透明度做層級差異

### 背景風格規則

背景圖不是獨立插畫，而是首頁祭壇背後的舞台背景。

正式風格固定為：

- 以真實地標骨架為主
- 加入輕度奇幻氣氛
- 不做重度奇幻改建

風格比例建議：

- `80%` 可辨識現實地標
- `20%` 奇幻氣氛與天氣演出

奇幻感主要來自：

- 天氣
- 光線
- 靈光
- 霧氣
- 材質氛圍

不可做成：

- 完全陌生的新神殿
- 重度奇幻建築改造
- 旅遊海報式寫實照片
- 有角色 / UI / 文字的完整插畫

### 背景構圖規則

背景必須同時服務：

- desktop 全景閱讀
- mobile 裁切
- 置中前景 UI 遮擋

正式構圖原則：

- 地標主輪廓需落在上半部，尤其是 upper-middle
- 左右兩側要保留輔助辨識元素
- 下半部中央只能放氣氛，不可放唯一辨識點
- 天氣戲可主要放在天空與上半部

也就是：

- 桌機版可看全貌
- 手機版即使中央被 UI 蓋住，仍能從上中輪廓與左右建築辨識地標

對應 prompt 原則應固定包含：

`designed for centered foreground UI occlusion and mobile crop`

### 背景產圖批次規則

每區不一次做滿全部景點。

正式節奏固定為：

- 每區先做 `1 個主地標`
- 先做 `3 張 trial`
- 通過後再補到 `6 張 final`
- 第 `2`、`3` 個景點要另外決定，不預設開做

trial 固定天氣：

- `clear-cloudy`
- `rain`
- `thunderstorm`

final 第一批固定天氣：

- `clear-cloudy`
- `overcast`
- `rain`
- `heavy-rain`
- `thunderstorm`
- `dense-fog`

### 背景 runtime 規則

- 正式背景 runtime 路徑固定為 `images/backgrounds/<city>/<district>/`
- `scene-line` 只以「當前背景地標 + 天氣狀態」組成
- 同一行政區若同一種天氣下有多張正式景點圖，應從該天氣可用景點池中隨機抽取
- 未命中 district 級正式圖時，回退到 `images/backgrounds/shared/` 的共享奇幻背景

### Rarity Glow Rules

- `common` 應讀成「有材質的普通卡」，不是弱版 `rare`
- `common` 主打象牙白卡框與細內光，外層 halo 應顯著弱於 `rare`
- `rare` 才正式進入白光發光感
- `epic` 使用暖金光，需明顯比 `rare` 更高貴
- `legendary` 使用厚重紫光，存在感必須高於 `epic`
- `hidden` 使用 logo 系藍光與異常感，辨識邏輯應和其他等級不同

### Mobile Density Rules

手機版不是桌機版等比縮放，而是同一套視覺系統下的較低密度版本。

目前已啟用的 mobile 規則：

- `central-altar` 需收斂間距與 padding，避免整體過滿
- `hero-title` 需下修到手機可讀但不壓滿畫面的級距
- `start-button` 可略縮，但 CTA 文案必須維持單行
- reveal card 在 mobile 的 `max-width` 固定為 `308px`
- 卡片背面與正面文字需跟隨卡片同步縮放，不可只縮卡片本體
- mobile 目標不是完整顯示所有背景細節，而是保留中央安全區的可讀與可玩性
- background 目標不是讓 mobile 看見完整全景，而是讓地標在裁切與遮擋後仍可辨識

安全框與圖資參照：

- `docs/superpowers/specs/2026-04-06-artwork-safe-frames-and-flip-design.md`

## 內容與文案規則

- Traditional Chinese 是主要產品語言
- 可用奇幻包裝詞，但要維持好懂
- 結果畫面以快速接受與下一步行動為主
- 不把內容寫成平台式資訊堆砌
- 不在結果頁塞入過多 secondary CTA

資料來源產品化規則：

- Google Sheet / fallback source state 屬於正式 runtime 狀態
- 但它不是目前首頁的第一級資訊
- 若未來要露出，必須以低干擾方式呈現，不可把首頁拉回資訊過載狀態

Weather source 規則：

- UI 上改顯示 `預計冒險地 3 小時天氣預報`
- 不需把 `中央氣象署` 或行政區名稱再重複寫成來源標示
- 若目前遠征地具備 CWA 鄉鎮 mapping，weather snapshot 應跟著該行政區

Choice item 描述原則：

- 短
- 具體
- 有感
- 支援快速接受

較佳例子：

- 麵量穩、出餐快，適合中午不想想太多
- 甜度好調整，適合下午提神
- 氣氛穩、距離近，適合下班後輕鬆坐一下

## 成功標準

- first interaction 在 30 秒內開始
- one round 在 2 分鐘內完成
- 使用者能立刻理解結果
- 體驗比普通隨機抽選器更好玩
- 行動按鈕足夠清楚，能自然接到下一步
